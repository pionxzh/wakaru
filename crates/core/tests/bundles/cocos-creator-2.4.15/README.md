# Cocos Creator 2.4.15 project-script bundles

`dist/` holds unmodified output of
`producer cocos-creator@2.4.15 web-mobile debug=true|false` for the scripts in
`src/`. Unlike `../cocos-creator-gen/`, which emulates the Cocos prelude with
browser-pack, these files come from the editor itself. It compiles each
TypeScript script with its bundled typescript 4.1.3 (CommonJS, ES5 target),
wraps it in `cc._RF.push(module, uuid, script)` / `cc._RF.pop()`, and packs
the scripts into its Browserify dialect. The release build is minified.

The editor is not an npm package, so `dist/` cannot be regenerated by a
script here. To rebuild it:

1. Download Cocos Creator 2.4.15 for macOS. The download URL is listed under
   `data["2d"]` in
   `https://creator-api.cocos.com/api/cocoshub/editor_version_list?lang=zh&ver=2.3.2`.
2. Copy `CocosCreator.app/Contents/Resources/templates/helloworld-typescript`
   into a new project directory. Set `"version": "2.4.15"` in its
   `project.json`, and copy `src/a.ts` and `src/b.ts` into `assets/Script/`
   (`Helloworld.ts` is the template's own script).
3. Run, from a GUI session (the editor needs a window server even on the
   command line):

   ```bash
   CocosCreator.app/Contents/MacOS/CocosCreator --path <project> --force \
     --build "platform=web-mobile;debug=true;buildPath=build-debug"
   CocosCreator.app/Contents/MacOS/CocosCreator --path <project> --force \
     --build "platform=web-mobile;debug=false;buildPath=build-release"
   ```

   The first build of a new project can fail while it compiles the engine;
   running it again succeeds.
4. Copy `<build>/web-mobile/assets/main/index.<hash>.js` to
   `dist/index.debug.js` and `dist/index.release.js`.

The registration uuids come from the `.meta` files the editor creates on
first import, so a rebuild changes them.
